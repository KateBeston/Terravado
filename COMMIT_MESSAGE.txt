Security: upgrade the Supabase stack (ssr 0.5.2 -> 0.12.7, supabase-js 2.45.4 -> 2.118.0)

Closes the @supabase/auth-js "insecure path routing from malformed input"
advisory, which couldn't be fixed by bumping supabase-js alone — the patched
supabase-js needs a matching @supabase/ssr, so both move together. This is the
coordinated stack upgrade, done and tested rather than rushed as a one-liner.

Changed
- @supabase/ssr 0.5.2 -> 0.12.7 and @supabase/supabase-js 2.45.4 -> 2.118.0 in
  both apps and the @terravado/core peer deps.
- No app code changes needed: the cookie integration already uses the modern
  getAll/setAll pattern (packages/core/src/supabase/{server,middleware,client}.ts),
  which is unchanged across 0.5 -> 0.12, and on Next 14 cookies() stays synchronous.
  Once ssr and supabase-js were aligned, the types resolved cleanly.

Verified
- auth-js advisory cleared in npm audit; total vulns down (23 -> 21).
- Both apps: tsc clean; next build green; booted on the new stack — /, /login,
  /modeller, /properties/[id]/foreign all 200, engine computes $105,600, no ssr
  or import errors. Engine 40/40.

Remaining audit items (unchanged, known): next's bundled postcss (build-time) and
glob/minimatch (dev/build tooling). Only a Next 16 major clears those — a separate
decision.
