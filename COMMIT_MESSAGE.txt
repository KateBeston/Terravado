CI: correct the Assurance workflow for the monorepo

The "Assurance" workflow was written for the old single-app layout (root
verify:engine / lint / build) and failed after the monorepo restructure. This
replaces it with a single root workflow for the workspace.

- Added .github/workflows/assurance.yml at the REPO ROOT (GitHub only runs
  workflows from the root). Installs the workspace once (npm ci), then runs the
  three gates that catch real regressions: engine assurance checks (npm run
  verify), typecheck of both apps, and a production build of each app.
- Removed the stale per-app workflow copies under apps/*/.github (GitHub ignores
  non-root .github, so they were inert and confusing).
- Dropped the Lint step: the apps have no ESLint config, so `next lint` prompts
  interactively and fails in CI. Re-add once an eslint config is in place.

Verified locally: npm run verify = 40/40; npm run typecheck (both apps) clean;
both apps build green.
